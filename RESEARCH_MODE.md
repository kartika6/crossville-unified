# Research Mode

Crossville supports fictional within-prototype demonstrations, not a validated experimental instrument. It records actions and participant entries without inventing performance measurements, research outcomes or inferred mental states.

## Setup
Choose Research mode, a scenario and condition; apply, then start the task. Export the existing session before resetting. Reset current scenario restores deterministic scenario content plus the common original project fixture, clears packets/workspaces/edits/logs and creates a new session ID. Scenario text is distinct for Recall, Branching, Updating requirements, Context selection, Cross-tool handoff and Provenance checking. All start with the same underlying fictional project to avoid inventing unrelated projects.

## Conditions
**Crossville:** normal structured context, library inspection, task relevance recommendations, packets, source references, approvals and selective sync are available.

**Baseline:** only a conventional narrative of the current shared source context, editable manual summary, clipboard/text download and task/session controls are available. Structured navigation, project export/import and canonical version card are hidden. Domain transitions also reject structured actions. Baseline does not receive structured recommendations or inspectors. Complete a task before changing conditions or leaving an active task. Reset between conditions to remove carryover. Setup and export controls are study-administrator affordances; this is not a locked kiosk.

The unstructured baseline narrative is derived from the same current shared context and pending suggestions as the structured condition, with only inline source labels and no structured controls. It is not a real AI-generated comparison. Baseline and structured materials have not been experimentally validated for difficulty equivalence; pilot them with the intended protocol.

## Logged events
Study session ID, condition, scenario, ISO timestamp, action type, actor, relevant IDs and detail. Events cover capture, comments, votes, detected conflicts, resolutions, context inclusion/exclusion, proposal submission/review, handoff creation/receipt, progress, participant-reported missing context, inspected sync recommendations, approval/decline/defer, private-session actions, task start/completion and scenario reset. Sync inspection records rule-based levels/reasons. No elapsed-time scores are automatically calculated. Manual note text can appear in progress/missing-context event detail; participants must use the fictional materials.

JSON exports retain complete event records; CSV quotes every field and doubles embedded quote characters, with CRLF rows and semicolon-separated item IDs. Both export all retained events, including session IDs, allowing later session filtering. Project export is a separate full-state backup and includes private simulation content; handoff packets do not.

## Example complete walkthrough
1. In Workspace capture a fictional conversation memory with a source reference.
2. Switch between You, Teammate A, Teammate B and Professor to cast category votes. Agree to categorize or create and resolve a disagreement.
3. Review the pending methodology proposal as You; approve only after inspecting rationale/impact. Observe canonical version and dependent task flags.
4. In Handoff builder select Codex, describe continuation, recommend context, inspect selections, generate a packet and transfer to simulated Codex.
5. Record progress/missing details. Optionally open private exploration; save notes, pause/exclude extraction, edit a suggestion and submit only reviewed fields.
6. Propose and approve a later method/constraint change in Workspace. Codex keeps its earlier context.
7. Inspect sync recommendation and before/after; decline, defer or approve selected deltas. Observe item updates and retained historical packet.
8. Return a finding from Codex to shared review; owner approval creates canonical context and future sync changes.
9. Complete task; export event JSON/CSV and optional project backup; reset before the next condition.

## Simulation boundaries
No real provider receives information. Keyword retrieval, extracted candidates and conversation replies are scripted. User switching represents local role simulation. Project permissions are prototype rules, not account isolation. No private participant AI history is necessary. No research outcomes have been claimed.

## Automated study conditions

The adaptive app offers A: manual baseline, B: automated opaque, C: automated explainable. A starts tasks without queued delivery and requires participant selection/summary/load. B and C run identical selection and delivery logic; only C exposes selection reasons, sources, exclusions and detailed event inspection. Shared project facts and seeded task content are constant. Settings restore v4 and issue a new session when switching condition. Switching is blocked during an unfinished study task. Export logs before resetting or changing condition.

The seven-scene guided demonstration uses meaningful milestones, not timed screenshots: inspect v4; privately explore action research in Claude; propose and approve as Professor to v5; start Codex development to trigger delivery; submit NotebookLM's two low-risk findings and approve to v6; inspect Codex sync; complete Codex work and approve the detected interruption question to v7. Back navigates earlier scenes without rolling back history. Restart/Reset restores the fixture. In condition A use the manual preparation area at the same task transitions; the story's automation explanations describe the experimental automated condition.

Pause, slow and single-step controls affect actual queued state transitions. JSON/CSV logs include session, condition, scenario/task, timestamps, event type, relevant IDs and recipient version. Full backups include private fictional notes. No performance scores or research outcomes are fabricated. The prototype is a local multi-person simulation; scripted AI responses and delivery acknowledgements are explicitly labeled.
